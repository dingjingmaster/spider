# 代码定义爬虫，只读 Web 状态页

用户明确取消通过网页新建/编辑爬虫，要求 Web 仅显示代码中实现的爬虫、执行状态以及成功/失败。该要求替代此前网页配置规则/原生 JSON 编辑器的产品方向，在当前未提交重构上继续修改。

- C 爬虫实现继续位于 src/spiders。实现类型注册后，由代码调用 crawler_add(registry, stable_code_id, implementation, config) 注册具体任务，名称、参数、周期均来自代码。不增加伪造的业务网站任务。
- main 在调度启动前调用 crawler_sync，将当前代码任务在一个 SQLite 事务中同步到持久化目录。稳定代码 ID 映射到已有数据库 ID，未变化配置不追加版本或重置 next_run。新增 code_spiders 辅助表，核心 SQLite user_version=3 保持兼容。
- 旧网页任务与历史记录保留；不在当前代码目录中的任务停用、取消未完成运行，不能继续自动调度。移除代码任务后保留其历史关联，重新加入相同代码 ID 复用原 ID。
- Web 模块只依赖状态模块；GET 查询健康、代码爬虫列表、运行历史、运行详情和事件。拒绝所有非 GET 请求；不提供新建、编辑、导入、试采集、手动运行、停止或配置/文件导出接口。响应不含规则快照、Cookie、认证头和代码参数。
- UI 改为自动刷新的状态看板，显示未执行、排队、运行、成功、部分成功、失败、取消、执行时间、数量、失败原因和当前进度。空目录明确提示还没有代码任务。保留 API token 的浏览器本地连接设置。
- JSON 工作流引擎可供代码任务复用。旧工作流网络/恢复/预览测试改由仅在 tests 下构建的 engine_fixture 驱动，不在产品加入测试控制开关或隐藏写路由。
- 继续保证不同爬虫并发、同一爬虫单线程，以及取消退出期间的防重。保留全部核心回归覆盖，新增代码目录同步和只读看板集成测试；Release 与 ASan/UBSan 完整验证。
