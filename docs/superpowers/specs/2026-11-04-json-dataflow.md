# JSON workflow dataflow

User approved the preceding six-part analysis for implementation. Keep pure C, SQLite and one workflow schema v2. Source lives under src/. Existing workflow semantics remain compatible.

## Contracts

- Extraction supports object/array/json in addition to existing scalar types. JSON responses preserve native JSON values; HTML values of these types must parse as JSON. Wrong object/array shapes fail. Optional absent/null remains null; required null fails.
- Every step optionally declares input (a template/value projection) and input_schema. Mapping evaluates against the incoming branch context before replacing input; schema applies defaults only to absent properties, then checks types/required/properties/items/additionalProperties. Supported schema types are string, number, integer, boolean, object, array, null, or an array of those. No implicit coercion. Mapping and checks run once before phase0 work, including group forks, and are shared by execution/preview.
- Preserve next_input. Add JSON Pointer reference expression {"$ref":"/steps/lookup/items/0/key.with.dot","default":0}; default is literal and used only for absent paths, not null/false/0. Existing dot templates still work. Reference expressions are reserved objects containing only $ref and optional default. Output limit 4MiB and nesting32 remain.
- transform step: optional value (default input), operations array 1..32. Pipeline operations: pick(JSON Pointer path, optional literal default), default(literal value, only null), rename(from/to direct object keys, collision errors), cast(type scalar, strict finite/range validation), trim(string), replace(old nonempty/new strings), filter(test using per-item input), map(fields expression using per-item input). Arrays limited to1000; contexts isolated; no scripts. join continues to handle object projection.
- request.response_json:true explicitly captures parsed full bounded HTTP JSON as response.json. response_body:false suppresses retained response.body; default keeps existing 64KiB preview. retain_steps optionally prunes context.steps to named IDs after next_input evaluates. Outputs remain available through persisted trace. Defaults remain explicit; no global writable JSON.
- Debug redaction copies values for presentation, never changes execution values. Built-in sensitive field names plus rule.sensitive_fields (up to64 names of1..80 bytes) are redacted recursively (including JSON-string bodies). Branch-local provenance is bounded to512 scalar values/1MiB and hidden from presentation; transforms consuming known secrets conservatively mark derived output. Large body retention is opt-out with response_body:false; arbitrary text secrets cannot be inferred reliably.
- New POST /api/preview/step returns {session_id,step_id,output,context,request,next_steps,notice}. Input {rule,step_id,context? (new sessions only),session_id?,dry_run?,item_index?,branch?}. Each call executes only the chosen step; no automatic network chain. request/transform/join/emit/condition are supported; emit returns data without saving. foreach previews one selected item (default first, explicit notice); parallel requires branch selection; downloads are not executed in preview. Server keeps unredacted branch context and temporary Cookie session, 16 sessions max, 10 minute TTL, 256 steps/session, bounded context. Rule changes require a reset/new session. dry_run resolves a request without sending it or committing context. Existing /api/preview request-only shape remains compatible. New preview endpoint and step trace responses are redacted.
- UI keeps full JSON and existing forms; adds input/schema/next_input forms, transform type, response capture controls, a JSON tree picker binding to URL/query/headers/json/input/next_input, dry request display, reset/continue preview controls. Reference bindings preserve types/escape arbitrary keys. Edit changes reset preview. Stale async responses cannot overwrite a newer rule/session.
- POST /api/preview/release with {session_id} releases an existing session. UI resets and discarded stale replies release their obsolete sessions; busy sessions remain alive only until existing references leave and reject all new/queued work.

## Alternatives and decisions

Automatic replacement of input loses original record keys and shared mutable global JSON races in parallel branches. Keep isolated branch contexts with explicit projection and optional schema. Reuse the existing execution/storage model; no schema migration is needed. Persist full responses only when requested; debug sessions remain temporary rather than writing test results to SQLite.

## Validation

Tests must cover nested values end-to-end into JSON POST, special-key references, absent/null/false defaults, input type failure before outbound HTTP, per-branch isolation, transformation errors and size limits, request rendering/encoding, preview Cookie/token continuity despite redaction, no preview persistence/downloads, session rule mismatch/reset/capacity, and stale UI responses. Run existing suite plus new focused C, Python and Node tests, then Release and ASan/UBSan/leaks. No commit/push/deployment requested.
