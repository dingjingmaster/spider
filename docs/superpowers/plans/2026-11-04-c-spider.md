# C Spider Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver a usable C/SQLite crawler with a browser-based rule editor.

**Architecture:** Folder modules under src; one application service shared by preview and persisted runs. Persistent SQLite request queue, bounded HTTP transfers and versioned rules.

**Tech Stack:** C11, CMake, curl, sqlite3, json-c, Lexbor, CivetWeb.

**Spec:** docs/superpowers/specs/2026-11-04-c-spider-design.md

## Global Constraints
- All source files are under src/.
- Preserve the user's empty CMake/src scaffold and implement in this checkout.
- No deployment, push or automatic commit.
- Browser automation, cron expressions and complete JSONPath are documented future extensions.

## Review Focus
- Malformed selectors/JSON/HTTP responses must produce errors rather than crashes.
- Failed persistence/downloads must not report success.
- Cancellation and restart must not leave running tasks permanently stuck.
- Credentials, arbitrary filesystem paths and active HTML must not leak into UI execution.
- Rules edited during execution must not change an existing run.
